2. OS 3 MÓDULOS ESSENCIAIS DO APP
------------------------------------------------------------------------------

MÓDULO 1: INSTALAÇÃO / REGISTRO EM CAMPO (AGENTE DE COMBATE A ENDEMIAS)
- Mapa em tela cheia mostrando a posição GPS em tempo real do agente em Carmo.
- Painel Flutuante (estilo Bottom Sheet do MotoJá / Escada):
  * GPS automático: captura latitude, longitude e precisão (metros).
  * Endereço automático: preenche Logradouro/Rua, Bairro/Microárea e Quarteirão oficial via cruzamento com os polígonos de Carmo.
  * Campo [ Número da Armadilha ]: input simples e direto (ex: "01", "12", "ARM-05").
  * Campo/Botão [ Foto da Instalação ]: aciona a câmera do celular para registrar o local exato da armadilha (ex: sob a árvore, no quintal, atrás do muro).
  * Botão [ REGISTRAR ARMADILHA ]: salva imediatamente com confirmação visual e sonora.
  * Funcionamento offline total (com IndexedDB para fotos e LocalStorage para metadados).

MÓDULO 2: PAINEL DE ACOMPANHAMENTO (MAPA E MONITORAMENTO GERAL)
- Visualização de todas as armadilhas no mapa territorial de Carmo.
- Marcadores com status visual (ex: verde = instalada recentemente / ativa; amarelo = aguardando recolhimento; azul = leitura de laboratório concluída).
- Ao tocar em um ponto ou selecionar na lista:
  * Card flutuante com dados completos: Número da Armadilha, Foto da instalação em miniatura (com clique para ampliar), Endereço e Quarteirão detectados, Data/hora da instalação, Última leitura de ovos.
  * Botão de rota direta (Google Maps / Waze) para fácil navegação do agente até a armadilha no dia do recolhimento da palheta.

MÓDULO 3: LABORATÓRIO SIMPLIFICADO (LEITURA DE PALHETAS)
- Interface direta sem necessidade de leitor de código de barras:
  * Campo de busca / seleção do [ Número da Armadilha ] (com sugestões rápidas das armadilhas ativas).
  * Campo [ Número da Palheta ] (ex: "P-01", "1", "A").
  * Campo [ Quantidade de Ovos ]:
    - Contador rápido com botões [-] e [+] e digitação direta.
    - Indicador automático: Positiva (ovos > 0) ou Negativa (0 ovos).
  * Foto opcional da palheta (para conferência visual).
  * Nome do Responsável / Técnico pela leitura.
  * Botão [ SALVAR LEITURA ]: vincula imediatamente a contagem à armadilha correspondente e atualiza o mapa de acompanhamento.

------------------------------------------------------------------------------

- Os dados tabulares (id, numero_armadilha, lat, lng, endereco, data, ovos) ficam no LocalStorage + IndexedDB, permitindo sync futuro via Cloudflare D1 se desejado.

       `syncStatus: 'sincronizado'`.

2. RESPOSTA: ONDE É MELHOR HOSPEDAR? (GITHUB OU CLOUDFLARE?)
   Nossa recomendação técnica é clara e unânime: **CLOUDFLARE PAGES + D1** (com código no GITHUB).
   
   Por que NÃO apenas no GitHub Pages?
   - O GitHub Pages só aceita páginas puramente estáticas (HTML/CSS/JS).
   - Ele NÃO tem backend, NÃO tem banco de dados SQLite/D1, e NÃO permite que um agente na rua
     envie uma armadilha para o servidor e essa armadilha apareça na hora no computador do administrador.
   
   Por que no CLOUDFLARE (Pages + Worker + D1)?
   - É a mesma arquitetura de sucesso que o Almir já usa no `D:\ESCADA` e no `D:\MOTOJA2IA`.
   - O Cloudflare Pages hospeda o aplicativo React com velocidade máxima global, HTTPS e PWA.
   - O Cloudflare Worker + D1 permite o banco de dados centralizado em nuvem sem custo.
   - O GitHub continua sendo usado, mas para a sua função principal: versionar o repositório de código (Git)!
   - Ou seja: **Código no GitHub + Deploy no Cloudflare Pages/Worker**. É o padrão ouro da indústria.

3. DIVISÃO PROPOSTA DE COMMIT E DEPLOY:
   - COMMIT LOCAL (GEMINI): O Gemini cria o `.gitignore`, executa o `git init`, adiciona os arquivos
     e faz o primeiro commit oficial na branch `main` no terminal local (`f:\Desktop\GPS OVITRAMPAS`).
